# ShowTrip · 跟着演出去旅行 🎤✈️

> 以演出为圆心的 AI 行程管家：用户只说「我想去看谁的演出」，从锁定场次、比价机票火车、订场馆周边酒店，到排出一份可以直接下单的 3 天行程单——全程基于飞猪实时数据自动完成。

**参赛**：2026 飞猪 AI 旅行创新大赛 · 自由方向
**构建平台**：阿里云百炼 Managed Agent + 飞猪 FlyAI Skill（flyai-cli）
**一句话**：别人做「以目的地为圆心」的行程规划，ShowTrip 做「以演出为圆心」——先锁票，再成行。

## 为什么做这个

演出经济正成为国内旅游增长最快的引擎之一：为一场演唱会跨城、跨省已成年轻人常规操作（「跟着演出去旅行」）。但现有旅行规划产品都以「目的地」为起点，看演出的人的真实决策链是反过来的：

**先有票 → 再倒推出发日期 → 比价交通 → 找场馆周边酒店 → 塞进周边游**

这条链路今天要横跨票务、机票、酒店、攻略四五个 App 手工拼装。ShowTrip 用一条五步管线把它变成一句话的事。

## 核心亮点

1. **演出优先的反向规划范式**：以「场次」为锚点锁定目的地城市与日期骨架（D1 抵达 / D2 白天游玩+晚上演出 / D3 补漏返程），再向交通、住宿、游玩展开——贴合追演人群真实决策链，区别于千篇一律的目的地规划师
2. **多品类真实数据串联**：一次规划调用飞猪 4 类实时数据（演出票务 keyword-search、机票 search-flight、火车 search-train、酒店 search-hotel、景点 search-poi），输出的每一条航班车次、价格、预订链接都真实可点
3. **跨城比价策略**：同程机票/火车自动比价择优（短途火车、长途飞机），并在推荐慢车但存在快航班时主动提示时间权衡——像一个真的会替你算账的朋友
4. **降级不降体验**：目标演出售罄/未开票时自动降级到在售演出池并如实告知，行程单附「追演锦囊」：散场打车动线、应援装备、返程缓冲等实战经验
5. **模糊价保守估算**：飞猪返回的区间价（如 `4xx`）按保守下限进预算表并标注「起」，预算总览永远不虚标

## 工作流

```
用户一句话（演出名 + 出发地 + 日期）
        │
        ▼
┌─ ① 意图解析 ──── 演出名 / 出发城市 / 日期 / 预算 / 人数
│
├─ ② 演出发现 ──── keyword-search 逐级降级：{演出名} → {演出名}门票 → 在售演出池
│                   从 title【城市】锁定目的地
│
├─ ③ 交通比价 ──── 机票×火车 去返 4 查并行，最低价择优 + 备选 + 时间权衡提示
│
├─ ④ 住宿游玩 ──── 场馆周边酒店优先（--key-words 体育馆），不足补市区；
│                   search-poi 取景点填入 D1 傍晚 / D2 白天 / D3 上午
│
└─ ⑤ 行程成稿 ──── 演出卡片 → 交通表 → 酒店小节 → Day by Day
                    → 预算表 → 追演锦囊，图片/预订链接按飞猪展示规范独立成行
```

## 复现步骤

### 方式一：阿里云百炼（推荐，参赛主路径）
1. 进入[百炼模型广场](https://bailian.console.aliyun.com/cn-beijing/model/market)，选择 **Managed Agent**，新建智能体（默认配置）
2. 智能体会话中执行：`npx skills add alibaba-flyai/flyai-skill`
3. 将 [prompts/system-prompt.md](prompts/system-prompt.md) 全文粘贴为系统提示词
4. 配置环境变量 `FLYAI_API_KEY`（[飞猪AI开放平台](https://flyai.open.fliggy.com/)控制台申请）
5. 发起测试对话：「想看李荣浩演唱会，11 月从杭州出发」

### 方式二：本地 CLI（本仓库的自动化管线）
```bash
npm i -g @fly-ai/flyai-cli
flyai config set FLYAI_API_KEY "your-key"   # 体验模式可跳过

# 演出名 出发城市 出发日期 [偏好城市]
node scripts/showtrip-pipeline.mjs "李荣浩演唱会" 杭州 2026-11-06 广州
# → demo/行程单-广州-2026-11-06.md
```
